# Rumics

Rumics — минималистичный приватный чат с комнатами и шифрованием сообщений на стороне клиента.

Проект сейчас находится на стадии MVP. Главная идея — сервер хранит только зашифрованные сообщения и зашифрованный ключ комнаты, а пароль и расшифровка остаются в браузере пользователя.

## Возможности MVP

- создание комнаты с ограниченным временем жизни;
- подключение по ID или ссылке комнаты;
- защита комнаты паролем;
- получение соли и зашифрованного ключа комнаты через API;
- генерация ключа комнаты в браузере;
- шифрование сообщений через Web Crypto API и AES-GCM;
- хранение в PostgreSQL только ciphertext и IV;
- автоматическое удаление истёкших комнат;
- каскадное удаление сообщений вместе с комнатой;
- получение новых сообщений через polling.

Сервер не получает пароль и plaintext сообщений. Однако текущая версия ещё не является полноценной production-системой: нет WebSocket, аккаунтов, сложной авторизации и защиты от злоупотребления известным ID комнаты.

## Архитектура

```text
Browser A ── encrypt ──> Go API ──> PostgreSQL
Browser B ── polling ───> Go API ──> PostgreSQL
Browser B <── decrypt ─── ciphertext + IV
```

Ключ комнаты создаётся в браузере. При создании он шифруется ключом, производным от пароля и соли, после чего на сервер отправляется только зашифрованная версия. Для сообщений используется ключ комнаты.

## Стек и версии

- Go `1.25.0`;
- PostgreSQL;
- `github.com/jackc/pgx/v5` `5.11.0`;
- HTML/CSS/JavaScript;
- Web Crypto API;
- `hash-wasm` `4.x` через CDN;
- HTTP polling вместо WebSocket на текущем этапе.

Точные версии Go-модулей зафиксированы в `go.mod` и `go.sum`. Версию `hash-wasm` сейчас задаёт URL CDN в `index.html`.

## Требования

- Go 1.25 или совместимая более новая версия;
- PostgreSQL;
- браузер с поддержкой Web Crypto API;
- доступ к CDN для загрузки `hash-wasm`.

## Настройка PostgreSQL

Для текущего MVP таблицы создаются вручную через SQL-клиент:

```sql
CREATE TABLE rooms1 (
    id TEXT PRIMARY KEY,
    expire TIMESTAMPTZ NOT NULL,
    salt BYTEA NOT NULL,
    key BYTEA,
    iv BYTEA
);

CREATE TABLE messages (
    id BIGSERIAL PRIMARY KEY,
    room_id TEXT NOT NULL REFERENCES rooms1(id) ON DELETE CASCADE,
    ciphertext BYTEA NOT NULL,
    iv BYTEA NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX messages_room_id_id_idx
ON messages (room_id, id);
```

## Запуск

Не добавляй пароль PostgreSQL прямо в исходный код. Сервер читает строку подключения из переменной окружения `DATABASE_URL`.

PowerShell:

```powershell
$env:DATABASE_URL = "postgres://username:password@localhost:5432/rumics_db"
go run .
```

После запуска открой:

```text
http://localhost:8080
```

Для проверки компиляции:

```powershell
go test ./...
```

## Проверка двумя пользователями

1. Открой сайт в обычном окне браузера.
2. Создай комнату и скопируй её ссылку.
3. Открой ссылку в режиме инкогнито.
4. Введи пароль и подключись.
5. Отправь сообщения из обоих окон.

Вторая вкладка получает новые записи примерно раз в 1,5 секунды. Для проверки с другого устройства используй IP компьютера в локальной сети вместо `localhost` и открой порт `8080` в firewall.

После полной перезагрузки страницы ключ комнаты исчезает из памяти браузера. Это ожидаемое поведение текущей zero-knowledge-схемы: нужно снова подключиться по паролю.

## API

- `POST /create` — создаёт комнату и возвращает ID и соль;
- `POST /api` — сохраняет зашифрованный ключ комнаты;
- `POST /connect` — возвращает соль, зашифрованный ключ комнаты и IV;
- `POST /messages` — сохраняет ciphertext и IV сообщения;
- `GET /messages?room_id=...&after_id=...` — возвращает новые сообщения.

## Roadmap

Планируемые изменения:

1. Сделать интерфейс более похожим на настоящий чат: время отправки, разделение своих и чужих сообщений, свои сообщения справа, чужие слева.
2. Добавить гибкие настройки времени жизни комнаты: удаление после бездействия, ограничение количества сообщений и другие параметры.
3. Заменить polling на WebSocket-архитектуру для доставки сообщений в реальном времени.
4. Добавить обработку небольших файлов, включая изображения, видео и аудио, с отображением файлов внутри чата.
5. Исследовать поддержку комнат более чем на двух пользователей. Для этого потребуется понятная схема идентификации участников в интерфейсе без аккаунтов.
6. Добавить нормальную систему миграций PostgreSQL с последовательными SQL-файлами и историей изменений схемы.
7. Перейти с HTTP на HTTPS и настроить TLS для безопасной передачи данных между браузером и сервером.

## Ограничения текущего MVP

- сервер не проверяет пароль комнаты напрямую;
- любой, кто знает ID комнаты, может отправлять запросы к её API;
- polling создаёт регулярную нагрузку на сервер;
- ключ комнаты хранится только в памяти страницы;
- нет имён пользователей;
- загрузка файлов пока не реализована.
